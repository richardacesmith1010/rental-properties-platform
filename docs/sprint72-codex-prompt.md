# Sprint 72 — Codex Implementation Prompt

## 1. Objective

Make all financial data editable and auditable by the owner. Charges can be edited, deleted, and manually created. Financial report KPI cards are clickable and drill down into the underlying records. Every financial number is traceable to its source records.

## 3. In Scope

### Part A: Charge CRUD Actions
- **Edit charge**: Owner can change amount, due date, description/category, and status
- **Delete charge**: Owner can delete any pending or late charge (not paid charges — those are financial records)
- **Create manual charge**: Owner can create a one-off charge (e.g., "Key replacement fee — $75") assigned to a specific lease
- **Waive charge**: Owner can mark a charge as "waived" (new status) which removes it from outstanding but keeps the record

### Part B: Charge Editing UI
- Each charge card gets an "Edit" button (pencil icon) and "Delete" button (trash icon)
- Edit opens an inline form or modal with: amount, due date, category dropdown, notes field
- Delete shows confirmation dialog: "Delete this $X charge due on Y?"
- "Add Charge" button at top of charges section opens creation form
- Category dropdown options: rent, late_fee, utility, maintenance, deposit, other (custom text)
- Waive option: "Waive Charge" button that changes status to "waived" with optional reason

### Part C: Financial Report Drill-Down
- **Open Receivables card**: Clicking it scrolls to/opens a detail panel showing every unpaid charge with tenant name, amount, due date, status, and edit/delete buttons
- **Net Income card**: Clicking it opens a breakdown: total income (paid charges) minus total expenses, with line items
- **Tenants in Ledger card**: Clicking it shows list of tenants with their balance

### Part D: Report Record Editing
- Every row in Rent Roll, Delinquency Aging, Tenant Ledger, and Accounts Receivable reports should be clickable
- Clicking a row expands it to show individual charges with edit/delete actions
- Expense records in Monthly P&L should also be editable (amount, category, date, description)

### Part E: Audit Trail
- When a charge is edited, store the previous values: `charge_edit_history` with old_amount, old_status, old_due_date, edited_by, edited_at, reason
- Show "Edited" badge on modified charges with tooltip showing who edited and when
- Deleted charges should be soft-deleted (add `deleted_at` column) rather than hard-deleted, so they can be audited

### Part F: Auto-Payment Amount Override
- Owner can change the recurring rent amount on a lease
- This affects future auto-generated charges (not past ones)
- UI: On the lease card or lease detail, "Edit Rent Amount" button
- Updates the `rent_amount_cents` on the lease record

## 4. Out of Scope

- Tenant editing charges (owner-only feature)
- Refund processing through Stripe
- Expense creation (already exists)
- CLAUDE.md / AGENTS.md edits

## 6. Implementation Requirements

### Part A: Migration

**File: `supabase/migrations/20260322_sprint72_charge_editing.sql`**

```sql
-- Add soft delete and waived status to rent_charges
ALTER TABLE rent_charges ADD COLUMN IF NOT EXISTS deleted_at TIMESTAMPTZ;
ALTER TABLE rent_charges ADD COLUMN IF NOT EXISTS notes TEXT;

-- Update status check constraint to include 'waived'
ALTER TABLE rent_charges DROP CONSTRAINT IF EXISTS rent_charges_status_check;
ALTER TABLE rent_charges ADD CONSTRAINT rent_charges_status_check
  CHECK (status IN ('pending', 'paid', 'late', 'waived'));

-- Charge edit history for audit trail
CREATE TABLE IF NOT EXISTS charge_edit_history (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  charge_id UUID NOT NULL REFERENCES rent_charges(id) ON DELETE CASCADE,
  edited_by UUID NOT NULL REFERENCES profiles(id) ON DELETE CASCADE,
  field_name TEXT NOT NULL,
  old_value TEXT,
  new_value TEXT,
  reason TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

ALTER TABLE charge_edit_history ENABLE ROW LEVEL SECURITY;

-- Only property owners can view edit history
CREATE POLICY "Property owners can view charge edits" ON charge_edit_history
  FOR SELECT USING (
    EXISTS (
      SELECT 1 FROM rent_charges rc
      JOIN leases l ON l.id = rc.lease_id
      JOIN units u ON u.id = l.unit_id
      JOIN properties p ON p.id = u.property_id
      WHERE rc.id = charge_id
      AND (
        p.owner_id = auth.uid()
        OR EXISTS (
          SELECT 1 FROM property_managers pm
          WHERE pm.property_id = p.id AND pm.profile_id = auth.uid()
        )
      )
    )
  );

CREATE POLICY "Property owners can insert charge edits" ON charge_edit_history
  FOR INSERT WITH CHECK (edited_by = auth.uid());
```

// editCharge(formData)
// Params: chargeId, amount_cents?, due_date?, category?, notes?, reason
// 1. Auth check — must be property owner or manager
// 2. Fetch charge, verify ownership chain (charge → lease → unit → property → owner)
// 3. For each changed field, insert row in charge_edit_history

// 1. Auth check
// 2. Verify ownership
// 3. Soft delete: SET deleted_at = now()
// 4. Insert edit history: field_name = 'deleted', old_value = status, new_value = 'deleted'
