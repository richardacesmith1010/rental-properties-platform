# Sprint 246a — No black screen at launch: a launch screen iOS can draw (iPhone tier, L3) — rev 3 APPROVED (rev 1 AWC → rev 2 AWC → rev 3 APPROVE)

## 1. Objective
On cold launch the iPhone app shows solid black for ~2 s before the doorway splash. Claude proved the cause from the
Simulator system log (iPhone 18 Pro, iOS 27, 2026-10-20):
- `splashboardd`: `XBLaunchStoryboardErrorDomain code 6 … Estimated size (29900800) is over limit` →
  SpringBoard: `Noting that the application com.domusbase.app has a bad launch image until it is updated` →
  later launches `Skipping launch request … due to denied app`. With no launch image, iOS shows black until the app's
  first frame. The launch storyboard's only content is the `Splash` image set: **2732×2732 px** per scale (≈30 MB
  decoded) — over SplashBoard's limit on this Simulator/OS. The same limit very likely applies on devices (same SplashBoard), but
  that is not yet proven on a phone; the fix is correct either way (Apple's guidance: launch screens are simple
  views, not full-screen bitmaps).
- Separately, Simulator builds are unsigned (`Signing.xcconfig:3 CODE_SIGNING_ALLOWED[sdk=iphonesimulator*] = NO`),
  which made SplashBoard fail earlier with `Security error -67056` (unsealed resources). With an ad-hoc signed build
  (`CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=-` on the command line) that error is gone and the size error remains.
Make the launch screen small and native so iOS can snapshot it, and sign Simulator builds ad-hoc so the Simulator
behaves like a phone.

## 3. In scope
1. **New launch layout.** Storyboard root = plain `UIView` whose background is a new color set `LaunchBackground`
   (Any #F3F4F6, Dark #0E0F11). Child = `UIImageView` showing a new image set `LaunchMark`: the doorway glyph only
   (from `resources/icon.svg` `id="mark"`, knob included), **tightly cropped to the glyph's bounding box**, transparent
   background, light doorway #0B0C0E / dark #FFFFFF (knob color unchanged). The image view is `scaleAspectFit`,
   centered on X and Y of the root view, with an aspect-ratio constraint (glyph width : height, computed once from the
   glyph's viewBox bounds in `assets.mjs` and written into the storyboard; report it), a **width = 312 pt** constraint
   at priority 750, and a required **width ≤ root width − 32 pt** constraint (16 pt margin each side). Result: 312 pt
   on 375/402 pt screens (matching today's ~310 pt doorway), 288 pt on a 320 pt screen.
2. **Assets.** `LaunchMark.imageset` at 1x/2x/3x (pixel size = the pt size above × scale, rounded), light + dark, PNG
   with alpha, generated by `assets.mjs` from
   `resources/icon.svg` (`id="mark"` group, same stroke recolor rule as `buildSplashSvg`). Every launch image must be
   ≤ 4,000,000 bytes decoded (width × height × 4). `assets.mjs` computes the 3x size before writing and **throws** a
   clear error if it exceeds the limit (no silent resize/crop). Remove `Splash.imageset` and the `splash.png` / `splash-dark.png` outputs
   once nothing references them (grep the repo, including `apps/ios/resources` and capacitor config).
3. **Capacitor splash background.** Remove `backgroundColor` from the `SplashScreen` plugin config in
   `apps/ios/capacitor.config.ts` and the copied `apps/ios/ios/App/App/capacitor.config.json` so the plugin's view
   uses the storyboard's adaptive `LaunchBackground` (no light flash in dark mode). Keep `launchAutoHide` and
   `launchShowDuration` as they are.
4. **Simulator signing.** `Signing.xcconfig`: `CODE_SIGN_IDENTITY[sdk=iphonesimulator*] = -` and remove the
   `CODE_SIGNING_ALLOWED[sdk=iphonesimulator*] = NO` line. Device (`iphoneos`) settings unchanged. Update
   `config.test.cjs` so simulator builds expect `CODE_SIGNING_ALLOWED = YES` and identity `-`, device unchanged.
5. Tests in §8.
